# Общий индекс новых диалоговых формулировок

После добавления `dialogue_triggers.json` возникла необходимость соединить 60 новых формулировок с общим поиском. Теперь `scripts/search_knowledge.py` индексирует `triggers`, сохраняет ссылку на утверждённый `target_case_id` и поднимает точные совпадения фразы на первое место после фильтра аудитории.

**Было:** 451 запись. **Стало:** 511 записей; прирост 60 записей — это ранее добавленные формулировки, а не 60 новых сгенерированных ответов.

Тест `scripts/test_dialogue_search.py` проверяет все 60 совпадений и их целевые сценарии, запрет выдачи закрытых модерационных примеров общему профилю и 10 детерминированных прогонов. `scripts/test_pragmatic_search.py` обновлён под новый размер индекса.

Диалоговый роутер дополнительно проверяет явно выбранный язык для контрастивных выражений: английскую фразу нельзя случайно обработать как русскую, и наоборот. Запрос не переводится автоматически. Для произвольной речи требуется отдельная модель или проверенный классификатор; этот индекс остаётся локальным и не выполняет сетевых запросов при каждом сообщении.


## Жизненный цикл локального cache — 02.11.2026

Поиск теперь держит LRU результатов **внутри одного SHA-проверенного экземпляра**
`KnowledgeSearch`, а не в декораторе метода класса. Это важно для длительно
работающих consumers: после замены валидированного snapshot старый объект поиска
может быть освобождён сборщиком мусора вместе со своим cache, а новый экземпляр
строит отдельный индекс из нового manifest.

`scripts/test_search_cache.py` полностью офлайн проверяет: освобождение старого
snapshot через weak reference, отказ от изменённого пакета при старом SHA-256,
приём тестового обновления только после обновления SHA в изолированном manifest,
разделение результатов старого и нового snapshot и границу LRU в 512 ключей.
Тест меняет только файлы во временном каталоге. Публичные языковые пакеты,
санкции, consumer-интеграция и живые боты этим изменением не затрагиваются.

## Динамический qa.v1-поиск для совместимых потребителей — 03.11.2026

Эталонный локальный `scripts/search_knowledge.py` теперь индексирует записи
зарегистрированных в manifest самоописанных `catalog.adapter=qa.v1`,
используя `catalog.records` и метки аудитории, а не список имён пакетов.
В актуальном снимке это 40 универсальных QA и 534 справочных ImPULS QA.
Точный запрос и одобренные aliases индексируются как точные фразы;
текст ответа и variants используются только для безопасного поиска.
Отдельная аудитория `impuls` может находить соответствующую справку,
но `all_ai_bots`, `community_bots` и `chat_moderators` не получают
ImPULS-only записи. Поля context остаются ограничениями вызывающего
приложения: индекс НЕ определяет адресность Telegram-сообщения, не выдаёт
санкции и не подтверждает доставку живому потребителю.

`scripts/index_contract.py` теперь учитывает все записи qa.v1 в точном
проверенном количестве индекса. `scripts/test_extended_knowledge.py`
проверяет поиск по оригинальному вопросу, alias, изоляцию аудиторий и
равенство счётчика индекса настоящему manifest. Перед публикацией обязательны
exact-head CI и post-main CI.

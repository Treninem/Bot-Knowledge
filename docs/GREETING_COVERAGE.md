## Контекст и совместимость

Сохранён старый интерфейс `reactions.greeting: list[str]`.
Добавлена необязательная метаинформация `greeting_catalog` с десятью группами
по десять вариантов: neutral, brief, day, listening, ideas, reflection,
interests, creative, practical, casual. Это группы **одного** intent.
Индексы указывают на тот же массив; копии ответов не создаются.

`scripts/greeting_catalog.py` — отдельный opt-in эталонный consumer с локальным
индексом групп. По умолчанию используется только neutral. Тематическую группу
должен явно выбирать вызывающий код на основании разрешённого контекста,
а не угадывать её из слова «привет». Приветствие с содержательным вопросом
не совпадает с чистым приветствием и остаётся другому обработчику.

```python
from greeting_catalog import GreetingCatalog
catalog = GreetingCatalog()
reply = catalog.reply('привет', addressed=True, local_permission=True,
                      group='neutral', recent=())
```

Для импорта добавить scripts в PYTHONPATH. Все флаги поступают от consumer.
По умолчанию адресация и локальное разрешение отсутствуют. Чувствительный
контекст, просьба молчать или отключённые приветствия подавляют ответ.
Последние ответы передаются на один вызов и хранятся **только у consumer**
в изолированной сессии; общая память и отправка данных отсутствуют.
При исчерпании группы возвращается repeat_suppressed, не повторный ответ.
Никаких действий модерации, изменения настроек и выдачи прав нет.

Старый consumer, читающий только массив строк, НЕ получает автоматически
новый выбор группы и анти-повтор. ConversationRouter не изменён.
Общий KnowledgeSearch ранее не индексировал reactions; его число записей
не изменяется. Здесь используется отдельный прямой индекс групп.
Интеграция нового selector в ImPULS и поведение живого Telegram не проверены.
До утверждения нужны consumer-тесты маршрутизации и контекста. Репозиторий
Treninem/Impuls из этой задачи не изменяется.

## Целостность, кэш и проверки

Обновлены pack_version и knowledge_version. SHA-256 dialogue обновлён
в manifest; остальные 24 записи SHA не изменены. Ключ снимка selector:
(knowledge_version, dialogue SHA-256). Повреждённый новый файл отклоняется.
Старый экземпляр сохраняет прочитанные строки; заменять его можно только
после успешного создания нового экземпляра. Не очищать живые кэши из этой задачи.

Локально выполнено 20 unittest-тестов на реальных изменённых данных и
изолированных временных фикстурах: 100 достижимых ответов, уникальность,
косметические близкие дубли, 7 существующих вариантов входящего приветствия,
отрицательные и смешанные запросы, права/адресация, язык, чувствительный
контекст, молчание, анти-повтор, изоляция и смена SHA/версии.
Это не полный локальный прогон всех 25 пакетов: получение полного checkout
в среде заблокировано DNS. Два исходных файла восстановлены из GitHub;
исходный dialogue проверен по его SHA-256. Другие исходные пакеты не подменялись.

Для полного checkout предусмотрено:

```
python scripts/validate_pack.py
python scripts/test_greeting_catalog.py --repository -v
```

Второй запуск проверяет SHA/JSON всех 25 настоящих пакетов и точные/близкие
дубли с ними. При недоступном файле тест завершается ошибкой, не пропускается.
Проверка близости строк не доказывает отсутствие всех смысловых повторов;
содержательная проверка по-прежнему нужна. В открытых PR #35/#36 находятся
отдельные технические FAQ, а не расширение dialogue.reactions.greeting.

Новый workflow явно checkout-ит PR head и сверяет git rev-parse HEAD.
До фактически завершённого CI статус публикации BLOCKED/ожидает проверки;
старый успешный merge-ref не заменяет эту проверку. Результаты CI фиксировать
в PR только со ссылкой на запуск и полным head SHA. Post-main не применим,
пока PR не объединён владельцем.

# Кратковременный фокус диалога (RU / EN)

Версия: `2026.10.30.9`. Новый переносимый модуль `scripts/turn_focus.py` дополняет, а **не заменяет** `resolve_referents.py` и `dialogue_session.py`.

## Решаемая проблема

Существующий резолвер выбирал объект только из списка, переданного при каждом вызове; отдельный session-router запоминал лишь недавно выданные ответы для подавления повторов. Новый `TurnFocus` позволяет приложению держать **ограниченный, явно подтверждённый** объект и обращаться к нему через короткие местоименные запросы вроде «Покажи его снова» и «Open it again». Если конкретная цель не подтверждена, неоднозначность остаётся и бот просит уточнить.

Класс не читает реальные переписки, не извлекает автоматически объекты из свободного текста и не угадывает, о каком человеке или документе идёт речь. **Приложение обязано** предоставлять кандидатов и явно вызывать `pin(id)` только после подтверждения пользователем/в своей проверенной логике. Пример с полями `id`, `label`, `gender` — совместим с резолвером. Удобно держать экземпляр `TurnFocus` отдельно для каждой изолированной беседы.

## Применение

```python
from turn_focus import TurnFocus

context = TurnFocus(ttl_turns=2, max_candidates=8)
context.present([
    {"id": "a", "label": "чертёж опоры", "gender": "m"},
    {"id": "b", "label": "эскиз входа", "gender": "m"},
], language="ru")
context.pin("b")  # только после подтверждения фокуса приложением
assert context.choose("Открой его.", language="ru", addressed=True) == {
    "status": "resolved", "ids": ["b"]
}
context.advance()  # вызывается ПО ОДНОМУ РАЗУ при каждом следующем ходе
context.advance()
context.advance()
assert context.choose("Открой его.", language="ru", addressed=True)["status"] == "no_context"
```

Приложение должно вызывать `advance()` на каждом ходе и `clear()` при закрытии сессии, переключении диалога, изменении владельца контекста или отказе от фокуса. Временная граница выражена **ходами**, а не секундами: это не автоматическая часовая очистка. Для реального TTL по времени требуется отдельная реализация в consumer.

## Границы доверия и отказ от действия

- **Нет общего состояния между чатами:** не используйте один экземпляр класса для разных бесед. В классе нет идентификаторов чатов и дискового сохранения.
- `present()` заменяет список целиком и снимает прежний фокус; `pin()` запрещает неизвестные ID.
- Смена языка, отсутствие контекста или превышение срока дают `no_context`; неподтверждённый, составной или конфликтный запрос — `needs_clarification`.
- Не подменяются прямые ссылки по названию или порядку. Отрицательные и цитируемые указания не превращаются в действия. Опасная команда сохраняет `confirm_required`. Возвращаются только идентификаторы, без автоматического удаления, мута, бана, пересылки, оплаты или прав.
- Текстовые данные объектов находятся только в оперативной памяти изолированного consumer. Пакет GitHub содержит исключительно искусственные ситуации. В логах нельзя публиковать или синхронизировать частные имена, метки и ID.
- Код детерминированный и работает локально. Это не доказательство общего понимания местоимений LLM и не подключение к AuroraFox / ImPULS.

## Набор и контроль

`packs/ru/turn_focus_scenarios.json`: 56 оригинальных синтетических ситуаций, 28 RU / 28 EN, **14 категорий**: мужские/нейтральные и женские ссылки, смена фокуса, порядковые, явные имена, отсутствие фокуса, многозначность, истечение срока, сброс, языковая граница, отрицание, цитата, опасные команды и явный запрос подтверждения.

Проверка уникальности нормализованных текстов и ID, отсутствие коллизий с предыдущими пакетами, порог токенного Jaccard 0.84, строгая политика аудитории, SHA-256, функциональные сценарии, adversarial-тесты, 10 циклов и 1000 локальных вызовов: `python scripts/test_turn_focus.py`. Формальная проверка пакета: `python scripts/validate_turn_focus.py`.

Любой работающий бот должен отдельно подтвердить правильную изоляцию чатов, вызовы `advance()`, безопасность pin() и собственные измерения задержки. GitHub Actions измеряет только CI runner.

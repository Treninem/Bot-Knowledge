# Локальный каталог followthrough T383–T386 (read-only)

Референсный `scripts/followthrough_stage_catalog.py` объединяет **четыре проверенные
staged-стадии**: T383 (+82), T384 (+82), T385 (+164), T386 (+82).
Суммарно: **410 подготовленных** ответов для 82 исходных намерений — **5 staged
на каждое**. Основной зарегистрированный QA-пакет остаётся 246 ответов
(3 на intent). Вся группа: 656/8200 = 8/100 на intent, ещё 7544.
**Новых текстов этот PR не добавляет** — они уже в предыдущих merge.

## Контракт

При создании каталога `FollowthroughStageCatalog(root)` каждая стадия
независимо проходит `StagedContextSelector`: SHA-256 зарегистрированного
источника, закреплённые Git blob SHA, историю родителей, счётчики,
уникальные ID и контекст. Каталог дополнительно проверяет все 82
канонических намерения, отсутствие точных нормализованных повторов
**между четырьмя стадиями**, суммарный объём 410 и отсутствие
подмены вопроса. Ключ кэша состоит из версии manifest и SHA-256
реальных байт manifest/четырёх стадий, а не только из строки версии.

`select(intent_id, approved_reply_ids, audience, context, addressed,
local_permission, recent_ids)` не угадывает смысл из фразы пользователя.
Только **внешний доверенный потребитель** может предоставить явно
проверенный reply-ID и контекст. Если чего-то не хватает, каталог
возвращает `None`. При совпадении нескольких разрешённых кандидатов
предпочитается новейшая стадия; `recent_ids` подавляет повторы.
Обход через цитаты, эмодзи или привилегии других чатов не реализован,
сеть, память, санкции и побочные действия отсутствуют.

Проверки:
`python -m unittest scripts.test_followthrough_stage_catalog -q`,
`python scripts/validate_pack.py`.
Тесты: 82 intent-ID, 410 staged-ID, 246 зарегистрированных ответов,
выбор каждого из четырёх исторических источников, отказы без
разрешения/при чужом ID, повреждение любого staged-байта, 1000
повторных локальных обращений. Это **не измерение** задержки реального
BotHost и не доказательство понимания произвольной речи.

Манифест и зарегистрированные SHA пакетов не меняются;
работающие кэши и ImPULS не трогаются. Каталог — только
офлайн-эталон для будущей отдельно проверенной интеграции,
живые боты новых ответов автоматически не получают.
Прежде чем говорить о готовом релизе, нужны exact-head CI
и post-main CI после фактического merge SHA.

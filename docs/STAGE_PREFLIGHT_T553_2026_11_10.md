# T553 — быстрый отказ при изменении исторического staged-пакета

Источник: актуальный `Treninem/Bot-Knowledge` main `5de01ea9d3acc9399d11017c36aab7e5e389a83b`. При переносе использована содержательно полезная часть Draft [#547](https://github.com/Treninem/Bot-Knowledge/pull/547), но **не его устаревшее дерево**: код добавлен к сегодняшнему перечню `STAGES` на свежем main.

## Изменение
Ранее `FollowthroughStageCatalog` сначала создавал дорогостоящие `StagedContextSelector` для всех исторических пакетов, включая проверку длинных цепочек, даже если один файл был изменён. Теперь перед этим выполняется линейная проверка неизменяемого Git blob SHA каждого `STAGES` по действующей таблице `_PINNED_STAGE_BLOBS` из `scripts/staged_context_selector.py`. Отсутствующий pin и повреждённый файл отвергаются **до** построения селекторов; после пред-проверки все прежние глубокие проверки остаются включёнными.

Перенесён исходный регрессионный тест из #547: набор всех STAGES должен совпадать с закреплёнными путями, подмена первого/среднего/последнего файла и удаление pin должны завершаться отказом прежде создания селектора. Никаких новых ответов, пакетов в manifest, изменения кэша или прав потребителей. Доступ к ImPULS только чтение не требовался.

**Draft до проверок**: необходим Python unittest и полный exact-head GitHub CI. Проверить SHA ref и совместимость с актуальным main перед merge; после merge подтвердить post-main. В случае успешного переноса #547 можно закрыть как superseded с объяснением; до подтверждения не закрывать его уникальную работу.

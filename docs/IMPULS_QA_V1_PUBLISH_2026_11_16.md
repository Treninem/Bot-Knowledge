Лимиты согласованы **только в qa.v1-валидаторе**: 2 МиБ на файл, при сохранении лимита 8 МиБ на суммарный снимок, прежних ограничений схемы, аудитории, приватности и прочих проверок. Workflow на PR выполняет `validate_pack.py`, `validate_qa_v1.py` и тест в Python обычном/`-O`, с `checkout` строго на head SHA и `fetch-depth: 0` для сравнения с базой. Большой [PR #666](https://github.com/Treninem/Bot-Knowledge/pull/666) содержит 4402 **неопубликованных** контекстных кандидата в H1–H103. Эти 60 ответов предназначены для поддерживаемого зарегистрированного `qa.v1`; **не прибавлять их второй раз к общей сумме уникальных ответов**, пока смысловые пересечения со staging #666 и PR #661–#665 не проверены. У #666 сохраняются его отдельные счётчики, никакие staging-файлы из этого PR в manifest не включены. После возможного merge требуется пересчёт общего принятого набора и обновление базы #666 относительно нового main без потери исходных кандидатов.

`qa.v1` разрешает максимум 8 строк `variants` на запись, поэтому целевые 100 ответов невозможно механически зарегистрировать в этом формате. Для остальных контекстных кандидатов нужен отдельно проверенный совместимый формат с маршрутизацией по роли и чату. **Публикация в main не подтверждает, что установленный ImPULS уже обновил свой локальный снимок.** Деплой, BotHost и кэш работающего бота не затрагиваются.

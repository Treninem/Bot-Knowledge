ImPULS main при чтении: `54b8a3a813fec82c1f953408942ba327eb181c37`. Исходники изучены по GitHub без записи в частный репозиторий.

Проверенные ограничения текущего потребителя:

1. [`src/bot/knowledge/catalog.py`](https://github.com/Treninem/Impuls/blob/54b8a3a813fec82c1f953408942ba327eb181c37/src/bot/knowledge/catalog.py): обычный `qa.v1` читает только утверждённые `records`; список `variants` ограничен **8** вариантами помимо основного `answer`. Структура `stage_type=supplemental_contextual_reply_pool` здесь отсутствует. Нельзя перенести H103 в manifest «как есть» и считать запись доставленной.
2. [`src/bot/knowledge/reply_catalog.py`](https://github.com/Treninem/Impuls/blob/54b8a3a813fec82c1f953408942ba327eb181c37/src/bot/knowledge/reply_catalog.py): для `reply_catalog.v1` предусмотрены группы `groups` (до **24** на набор), максимум **100** ответов на один набор; суммарный лимит `MAX_REPLY_VARIANTS=16384`. Для применимости различаются структурированные `binding`, условия `requires`, `avoid_cues`, `contexts`, подтверждённые факты caller. Свободный `context_note` кандидата H103 не заменяет структурированную связь и не доказывает уместность ответа.
3. [`src/bot/knowledge/shared.py`](https://github.com/Treninem/Impuls/blob/54b8a3a813fec82c1f953408942ba327eb181c37/src/bot/knowledge/shared.py): загрузка идёт по проверенному опубликованному manifest, с локальным снимком и SHA. Установленные в этом SHA лимиты: `MAX_PACK_BYTES=4 MiB`, `MAX_TOTAL_BYTES=16 MiB`; рабочий критерий этой задачи для опубликованного снимка остаётся **8 MiB**, подтверждённый отдельно в Bot-Knowledge. Увеличение лимита в consumer не является разрешением превышать лимит публикации.
4. [`src/bot/knowledge/composition.py`](https://github.com/Treninem/Impuls/blob/54b8a3a813fec82c1f953408942ba327eb181c37/src/bot/knowledge/composition.py): прямой ответ строится из валидированного `qa.v1` и учитывает язык, аудиторию, контекст и тему. Это не подтверждает вызов контекстного selector для новых H103-условий в живом чате.

**Вывод:** H103 пригоден для редакционного отбора как staging; перенос 102 кандидатов в текущий `impuls_help_qa.json` с 100 ответами на намерение невозможен без нарушения текущего контракта `qa.v1`. Технический путь: отдельно отобрать семантически разные ответы, сгруппировать в `reply_catalog.v1` с настоящими проверяемыми bindings и тестами отрицательных условий, либо использовать максимум 8 дополнительных `qa.v1` variants при доказанной уместности для всех контекстов. Нужны размерный расчёт, SHA/manifest-инвалидация, тесты потребителя на действительном head и подтверждение фактической доставки; до этих шагов **не объединять**.

Данные ImPULS не изменялись, приватный код не копировался в публичные пакеты. В документе только названия публично безопасных API-контрактов, ограничения и пути к проверенному SHA исходника.

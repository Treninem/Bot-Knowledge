# Безопасное обучение и публикация новых знаний в GitHub

**Цель владельца:** все ИИ-потребители способны обнаруживать переносимые полезные навыки; общая библиотека получает их без потери приватности. **Текущий статус**: правила, offline-CLI кандидата, PR-процесс и проверка. **НЕ работает автоматически** live-запись от ботов и не выданы write токены клиентам.

## Двухконтурная схема
```text
Чат → приватный контекст конкретного продукта (без GitHub-токенов)
     → локальные агрегаты/повторяющиеся исправления (TTL, согласие)
     → обобщение в короткое правило без исходных цитат
     → независимая проверка приватности/качества + synthetic tests
     → `scripts/prepare_knowledge_candidate.py` (локальная проверка)
     → доверенный публикатор отдельной учётной записи
     → новая ветка/PR → exact-head CI → ручное утверждение → main CI
     → HTTPS-манифест, SHA-256, локальный cache/rollback у каждого бота
```

## Ограничения
- **Не** делиться секретами, именами, реальными сообщениями, ID, локальными правилами, обвинениями и действиями против конкретных участников.
- Отдельный бот **не имеет** прав записи `main`. Его формулировка — только кандидат. Защищённый публикатор может сделать **PR** после подтверждённого обзора, но ни он, ни workflow не обходят CI.
- Исходные кейсы должны быть синтетическими и разнообразными, избегать дублей и пустых перефразирований.
- Классификация тонов, сарказма, мата и обходов **не** является санкцией.
- Скрипт фильтра — дополнительная защита, **не гарантия анонимности**: каждый кандидат требует человеческого редакторского обзора.

## Формат кандидата
```json
{
  "candidate_id": "shared_rule_example",
  "statement": "Не считать короткую цитату оскорблением без контекста и локального правила.",
  "when": ["сообщение содержит цитату другого участника"],
  "avoid": ["цитата является частью прямой атаки на адресата"],
  "audiences": ["chat_moderators"],
  "origin": "synthetic",
  "reviewed": true
}
```
Запуск только **в доверенном изолированном окружении**, не над сырым логом:
```sh
python scripts/prepare_knowledge_candidate.py --input /tmp/candidate.json --output /tmp/approved_candidate.json
```
Результат находится **вне публичного репозитория**. Далее доверенный maintainer вручную сверяет содержание, подбирает существующую категорию, проверяет уникальность, делает новую ветку и PR с изменёнными пакетом, manifest/version/SHA и тестами. Пока нет отдельного проверенного безопасного publisher consumer, бот не может напрямую публиковать материалы. Команды публикации и выдача токенов в публичную документацию не включены.

Локальный `scripts/build_skill_draft.py` собирает только проверяемый черновик пакета и манифеста из уже рассмотренного кандидата и точного reviewed skill. Вывод создаётся вне базового репозитория; перед выдачей проходит существующий preflight. Скрипт не отправляет PR, не имеет токена записи и не заменяет редакторское решение. Живой publisher по-прежнему не реализован.

## Единый формат каждого отчёта
`дата | head SHA | уже в main? | файлы | новые уникальные записи | удалённое/изменённое | точный CI (тесты запущены?) | post-main CI | доставлено в какие боты | блокеры/следующий безопасный шаг`.
Отдельно считать только **новые** материалы, не перефразированные копии. При отказе Actions запуск без шагов — `BLOCKED`, а не `PASS`.

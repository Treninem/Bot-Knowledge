# T406–T410: безопасный выбор последних staged-ответов (08.11.2026)

В reference-selector `scripts/staged_context_selector.py` список разрешённых staged-файлов ранее обрывался на T405. Поэтому T406–T410 нельзя было получить через этот пример даже при явном подтверждении конкретного ответа. Новое изменение **не подключает** staged-файлы к живым потребителям: оно добавляет только пять проверенных, явно разрешённых путей для тестового чтения с жёстко закреплёнными Git blob SHA.

При открытии каждого из T406–T410 проверяются фактические bytes/Blob, цепочка T383 до предыдущей стадии, canonical question IDs, исходный manifest SHA-256, полные накопленные счётчики, отсутствие повторов в исторической цепочке и неизменность назначения `all_ai_bots` / read-only / direct address. Неизвестный T411, непрошедший review, автоматически не разрешается. `StagedContextSelector.select` по-прежнему требует `approved_reply_ids` типа `frozenset`, подтверждённую аудиторию, контекст и разрешение; отсутствие хотя бы одного условия даёт `None`.

Новые регрессионные тесты `scripts/test_recent_followthrough_selector.py` проверяют все 82 intent для каждой из пяти стадий, запреты контекста/разрешений/повторов, отвергают подмену bytes T410 или предка T409 и неизвестный будущий путь. Прогон запускается через стандартный read-only `quality.yml`, без ручного платного Actions. Не изменялись `manifest.json`, зарегистрированные JSON-пакеты, разрешения ботов, кэш и ImPULS.

Это улучшение возможности **безопасной ручной проверки** staged-контента, а не публикация или автоматическое подключение новых ответов к ImPULS/AuroraFox.

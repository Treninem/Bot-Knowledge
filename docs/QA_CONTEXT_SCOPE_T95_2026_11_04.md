# T95: контекстная изоляция поиска qa.v1 — 04.11.2026

Основа: BK main `23871ed224cbe0d9636c841fd48e3f43bdd3ed1b`, manifest `2026.11.04.026`, 38 пакетов. Существующие Draft #214 (справка/версия .027), #219 (модерационная справка), #220 (лимит снимка) не изменялись. Этот независимый PR не затрагивает `manifest.json`, `packs/`, версии или файлы ImPULS.

Проблема: `scripts/search_knowledge.py` проверял аудиторию записей qa.v1, но игнорировал `contexts`. Поэтому при прямом запросе в ЛС поиск мог выдать групповой справочный ответ, даже если запись помечена только `group_addressed`. Это не исправление генеративной модели и не доказательство поведения живого бота.

Исправление: `KnowledgeSearch.search(query, audience, limit, *, context=None)` умеет принимать **явный доверенный контекст** `direct`, `private`, `group_addressed` и отсекает несовместимые qa.v1 результаты **до ранжирования**, включая точные алиасы. При `context=None` сохранено прежнее поведение для существующих потребителей; неqa.v1 записи имеют прежнюю семантику поиска. Контекст включён в ключ локального LRU-cache. CLI дополнен опциональным `--context`. Фильтр сам не устанавливает факт адресованности, права, настройки группы или результат действий — это ответственность вызывающего потребителя.

Данные и размер: **0 новых пакетов, 0 новых ответов, 0 байт прироста снимка** (manifest и все пакеты остаются нетронутыми). Лимиты отдельного пакета 2 MiB и consumer #383 8 MiB не меняются; текущий общий объём требует проверки локальным валидатором на свежей копии.

Проверки: синтетический offline-тест `scripts/test_qa_context_scope_t95.py` охватывает group/private/direct, общий fallback, специфическую аудиторию ImPULS, алиасы, backward compatibility, раздельный cache и ошибочные значения контекста. В доступной Linux-среде выполнен **точный GitHub-файл теста (проверен blob SHA Git `b0e757db42d744189a154de6c52f0946878d0e0c`) на изолированной копии эквивалентной части поискового модуля: 23/23 PASS**, и `py_compile` теста и копии модуля. Это **не** прогон полного модуля и не тест полного репозитория. Полный checkout на D:, запуск теста против полного оригинального модуля, `python -B scripts/validate_pack.py`, consumer #383, exact-head CI и post-main **не выполнялись** из-за недоступности D:/GitHub DNS и запрета платных Actions. Нужна локальная проверка точного head, затем отдельное решение о merge без обхода защит.

# Общий контур знаний: ImPULS ↔ Bot-Knowledge ↔ AuroraFox и будущие ИИ-боты

**Решение владельца от 29.10.2026. Статус: целевая архитектура, а не разрешение немедленного изменения всех проектов.**

## Единый первоисточник переносимых умений

Публичный репозиторий **Treninem/Bot-Knowledge** — централизованное версионное хранилище общих языковых и прикладных навыков для **всех** программ Treninem, использующих искусственный интеллект. Боты и AuroraFox **не должны обмениваться знаниями напрямую или подключаться друг к другу ради обучения**. AuroraFox сохраняет свой собственный локальный Core, Knowledge, Memory, LoRA/Evolution и автономную работу без Интернета. Bot-Knowledge — только необязательный источник дополнительных проверенных навыков, **не замена Core и не единственное место сохранения опыта**.

Логическая схема:

    ImPULS SQLite [частная память чата]  ─┐
    будущие ИИ-боты [частная память]       ├→ [безопасный локальный агрегатор]
    AuroraFox [личная память/Core]         ┘          ↓
                                      [кандидаты без исходных сообщений]
                                                   ↓
                                [схема + PII/privacy + качество + обзор]
                                                   ↓
                                       [GitHub PR + CI + approval]
                                                   ↓
                          Treninem/Bot-Knowledge main (версии, SHA)
                                       ↙        ↓          ↘
                             ImPULS (кеш)  AuroraFox (кеш) другие боты

**Секреты, сообщения и история конкретного чата никогда не попадают в публичный GitHub.** Удаление опубликованной строки из новой версии не удаляет историю Git. Если безопасно обобщить нельзя, кандидат не экспортируется.

## Условия доступа для всех продуктов
1. **Читать** по HTTPS доверенный `manifest.json` и только пакеты, соответствующие версии и локальному профилю продукта; проверить схему, SHA-256, максимальные размеры и содержимое. Повторяющееся обращение в GitHub на каждое сообщение **запрещено**. Нужный индекс/шаблоны — в ограниченном локальном кеше, обновление фоновой задачей с таймаутом. При недоступном репозитории применять последнюю валидную копию или локальные знания.
2. **Отбирать** по назначению: универсальное `social`, `moderation_language` для ботов-модераторов, `bot_help` только для ботов с соответствующими функциями. AuroraFox может взять `social` и общие языковые стили, не загружая в свой runtime знания Telegram Stars, мутов или роли владельца отдельного чата. Будущие версии введут профили `profiles/<product>.json` / каталог независимых сегментов; пока один `skills.json` небольшой и допускает выбор по `kind` после чтения.
3. **Не доверять** общему пакету менять местную политику: он может подсказать формулировку, но не выдаёт полномочия, санкции, платежи, команды и системные настройки. Согласованные правила конкретного чата, настройки пользователя и собственная безопасность продукта выше общих подсказок.
4. **Писать** не напрямую в `main`, а через очередь проверяемых кандидатов. На BotHost и пользовательских устройствах нет GitHub токена на запись. Изолированный процесс-публикатор (например, доверенная GitHub App в GitHub Actions) с отдельной минимальной ролью создаёт PR. Его права, секреты и workflow должны пройти отдельный аудит. Все опубликованные абстракции проходят ревью и CI; без принятия PR данные **не становятся общими знаниями**. GitHub не заменяет очередь событий/транзакционную БД.
5. **Следить за версиями и качеством:** семантическая версия схемы, номер релиза и checksum, защита от подмены/отката к неожиданной старой версии, совместимость, телеметрия только агрегатная и без личных идентификаторов, восстановление последней исправной версии.

## Что сохраняется, а что никогда
- **Можно:** переносимое правило «при жалобе не объявлять виновного до проверки», типы намерений, нейтральные варианты поздравления, условия когда шутка неуместна, обезличенный учебный пример ложного срабатывания на Unicode-подменах, общий безопасный юмор собственной редакции.
- **Нельзя:** оригинальный пост из Telegram; дословная уникальная шутка из чата без права повторного использования; описание личной трагедии/болезни; имена/ID/телефоны, пользовательские профили, история банов; реальные настройки конкретной группы, сумма кошелька, токены/ключи/коды доступа; информацию, по которой можно косвенно узнать человека.
- **Автоматическое обучение** означает локальный сбор обезличенных оценок и **кандидатов** на общий навык; само по себе не даёт право автоматически коммитить в публичный `main`.

## План миграции AuroraFox от прямой схемы
В AuroraFox уже имеются **отдельные следы старого контракта** `aurorafox.impuls.community.v1` в `api/community_learning.py` и `evolution_engine/integration/community_learning_bridge.gd` (HTTP события / pull / ack). **Не удалять файлы и API без проверки вызовов и обратной совместимости.** План будущего независимого блока:
1. Зафиксировать текущий main, все ACTIVE claims, master log, roadmap и принятые ADR. Записать будущую работу как `PARALLEL_NON_BLOCKING`, без срыва текущих критичных выпусков.
2. Проверить, используется ли старый прямой мост сейчас, и кто зависит от него; выключать/удалять только по контрольному тесту, не теряя локальные знания и без перепривязки личных пользователей.
3. Реализовать **опциональный read-only** импортер отобранных `social`/safe language пакетов Bot-Knowledge в AuroraFox Memory/Core Knowledge с версией, offline кешем, origin metadata, конфликт-приоритетами и откатом. Core остаётся первичным и работает офлайн.
4. Локальный sanitizer + review → кандидат для публикации, **без сырой памяти AuroraFox** и прямых сообщений другим ботам. Публикатор PR отдельно от клиента.
5. Синтетические тесты: нет сети, испорченный SHA, старые версии, другое приложение, несоответствующий пакет, повторное обновление, недоступный GitHub, запрет раскрытия личных сведений, отсутствие регресса Core/Evolution.
6. Только после прохождения тестов и согласованной миграции удалить устаревшие прямые интеграционные пути/документацию, сохранив временную обратную совместимость при необходимости.

**Ограничение:** данный документ сам по себе не меняет релиз AuroraFox, не переписывает старый API, не переносит пользовательские данные и не включает фоновую запись в общий публичный GitHub.

## Текущее содержимое и масштаб
- Схема v1 — `intents.json`, `styles.json`, `dialogue.json`, `safety.json`, `skills.json`.
- Пакет `skills.json` расширяется нейтральными сценариями: поздравления, поддержки, молчания, деэскалация, разные стили, вопросы владельцу чата, объяснения команд и осторожный язык модерации/антиобхода.
- Навыки **декларативные**. Не считать их гарантией смысловой точности ИИ. Выбор в реальном разговоре требует отдельного контекстного движка, настройки уместности и разрешения автономности.
- Принимать только после локальной валидации, GitHub CI, точного SHA, тестов отрицательных случаев и отдельного теста на устройстве/хостинге.

## Процесс для будущего ИИ-бота
Первым шагом его разработки открыть `Treninem/Bot-Knowledge/AGENTS.md` и этот документ; взять необходимые подтверждённые универсальные навыки, затем развивать только свои функции и частную базу. Любой найденный общий полезный навык **предложить сюда через безопасную очередь кандидатов**. Дублировать целую языковую библиотеку в каждом проекте без причины не нужно.

## Планы и приоритет
Это **архитектурное дополнение**, а не приказ прерывать активные PR. ImPULS продолжает свои игровые/защитные блоки и новые социальные навыки лишь отдельными проверенными этапами. AuroraFox переходит на этот контракт при следующем безопасном независимом этапе, соблюдая свой master log и ADR. Не рекламировать «всё автоматически обучается», пока не реализована и не проверена сторона publisher/approval.

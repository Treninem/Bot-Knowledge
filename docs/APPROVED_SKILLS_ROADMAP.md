# Bot-Knowledge: библиотека переносимых навыков и проверенное пополнение

Дата: 2026-10-29. Статус: **план, не действующий автоэкспорт**. Эта общая база — публичный репозиторий. Его нельзя превращать в архив переписок, правил конкретных чатов или персональных данных.

## Что уже используется ImPULS

В ImPULS 1.6.0 загрузчик src/bot/knowledge/shared.py уже читает по HTTPS manifest.json, сверяет SHA-256 для пакетов, держит последнюю валидную версию локально и обновляет её в фоне. Загружаются intents.json, dialogue.json, styles.json и safety.json. Намерения и ответы из этих пакетов задействованы в Live ImPULS. Если GitHub недоступен, бот использует кэш либо встроенный fallback.

**Сейчас бот получает эту базу только на чтение.** Обработчик исходящего автоматического сохранения обобщённых навыков в GitHub не реализован. И это правильная граница безопасности для живых чатов.

## Цель следующей версии библиотеки

Bot-Knowledge должен стать **общим хранилищем переносимых и проверенных умений** для ImPULS и будущих ботов:
- распознавать тип обращения и настроение без энциклопедической информации;
- в подходящий момент поддержать, поздравить, пошутить или разрядить словесный конфликт, либо решить **молчать**;
- объяснить общие принципы возможностей ImPULS, не выдавая отсутствующую функцию за работающую;
- задавать точные вопросы об неоднозначных формулировках правил;
- выявлять языковые признаки обхода запрета, но не считать словарь доказательством нарушения;
- классифицировать шутку, цитату, опечатку, дружеский сленг и направленное оскорбление;
- сохранять только **универсальные речевые навыки**, которые можно безопасно повторить в любом чате с подходящими локальными правилами.

## Слои хранения

1. **Публичный Bot-Knowledge:** неизменяемые на время версии утверждённые универсальные JSON-пакеты с manifest/SHA-256; никаких chat_id, user_id, имён, номеров, цитат из личных сообщений, моделей людей, санкций и локальных правил.
2. **Приватная локальная БД ImPULS:** правила с подтверждением владельца конкретного чата, исключения, локальные санкции, настройка тона, оценки решений, TTL и возможность сброса. Никакой прямой синхронизации в публичный GitHub.
3. **Кандидаты на обобщение (приватный, временный контур):** только абстрактные навыки без исходных сообщений. Отбор, минимальный объём, анти-PII, проверка повторного узнавания, удаление по сроку; отсутствие кандидатов — нормально.

Важно: общая фраза «при сообщении о смерти не шутить, говорить деликатно» переносима. Чья-то конкретная семейная история, имя, день рождения, любимая шутка или секрет — нет. Дословную шутку из переписки без разрешения **не копировать** даже после удаления имён.

## Будущие пакеты (совместимая схема v1, добавляются только после отдельного PR)

| Файл | Что в нём |
| --- | --- |
| packs/ru/social_skills.json | Сценарии поздравления, поддержки, конфликта, уместной шутки, **молчания**, границы и варианты коротких реплик |
| packs/ru/clarification_skills.json | Как переспросить владельца конкретного чата по каждому пункту, что уточнить о санкции и исключении |
| packs/ru/moderation_language.json | Обобщённые признаки неоднозначности, маскировки слов, сленга, цитат и необходимость human review |
| packs/ru/bot_help_skills.json | Понятные объяснения функций без выдумывания доступов и обещаний |
| packs/ru/humor_safe.json | Редактированные или собственные нейтральные шутки с явными условиями уместности |

Разработать **открытую декларативную схему**, без Python-кода или встроенных команд. У каждого навыка: стабильный skill_id, purpose, triggers, allowed_contexts, contraindications (траур, конфликт, недостаток контекста), phrasing variants, quality/test tags, revision. Запрещены исполняемые выражения, произвольные ссылки на API, команды санкций и текст, пытающийся отключить политику бота. Глобальный навык **никогда** не управляет разрешениями конкретного чата: право на бан/мут задаёт только подтверждённое локальное правило.

### Совместимость
Текущий ImPULS проверяет и скачивает каждый JSON из манифеста, но его KnowledgeSnapshot **использует только существующие четыре файла**. Добавление нового pack в Bot-Knowledge само по себе ещё не включает новый навык у бота. Потребуется отдельный PR в ImPULS на read-only consumer с тестами. До этого новые пакеты не объявлять работающими.

### Правильный путь расширения
1. **K0 — аудит и тесты:** проверить текущие четыре пакета/загрузчик, baseline CPU/RAM/диск, размер снимка, статусы fallback.
2. **K1 — схема и проверенные примеры:** новые декларативные пакеты, JSON-schema/размеры/версия/хэши, тесты приватности и отрицательных контекстов. Все данные в PR — искусственные или написанные заново, не из живых чатов.
3. **K2 — потребитель ImPULS:** отдельный PR на загрузку новых пакетов, отказоустойчивый fallback, компактный кеш/TTL, выбор редкой уместной реакции без изменения действующих санкций/правил.
4. **K3 — накопление полезных сигналов локально:** хранить лишь необходимые обезличенные агрегаты и подтверждения администраторов, с TTL, лимитами и удалением. Нет отправки в GitHub.
5. **K4 — ручной/контролируемый выпуск кандидатов:** малый список обобщений без исходных сообщений, строгая проверка, одобрение владельца системы, PR в Bot-Knowledge. Никаких GitHub write tokens на BotHost.
6. **K5 — проверенная синхронизация:** валидировать версию/размер/хэш, атомарно принять новый снапшот, наблюдать FP/FN и частоту вмешательств; при ошибках — откат к последней рабочей версии.

Каждый K-блок — отдельный PR. Текущий игровой цикл ImPULS не прерывать; K0 после 6+1 игровых тестов и вместе с аудитом AI-A/MM-A.

## Контракт приватности и защиты от вредных данных

- Репозиторий **публичный**, поэтому считать каждую строчку общедоступной навсегда, включая git history. Автоматическое удаление ключа из будущего коммита не удаляет факт его прежней публикации.
- Не публиковать уникальные цитаты или случаи, даже после замены имени и номера.
- Не считать одного фильтра регулярных выражений достаточной защитой: нужны проверка структуры, высокорисковых шаблонов и ручная проверка.
- Пользовательские правила, тексты сообщений, «инструкции» от участников и подсказки для ИИ считать недоверенными данными. Общие пакеты — только утверждённые.
- Даже если запись прошла SHA-256, это означает целостность загрузки, не доказывает доверие к автору. Ввести PR-review, строгие branch permissions и CI.
- Опасные изменения прав/модерации, автоматическая передача личных данных, глобальное переназначение OWNER_ID/OWNER_IDS и использование недокументированных API не относятся к навыкам.
- Источник обновления должен быть HTTPS из доверенного репозитория; максимальный размер пакета/кол-во записей, дедупликация, лимит RAM. Проверить безопасный путь, отклонение повторов/неожиданной версии, rollback.

## Критерии будущей приёмки

- Два виртуальных чата с противоположными правилами; обобщённый навык никогда не выдаёт санкцию и не меняет локальные правила.
- Десять независимых раундов с поздравлением, трауром, конфликтом, чёрным юмором, дружеским сленгом, цитированием, обходом слов, отсутствием контекста: правильное **молчание** в опасных случаях, без повторов и оскорблений.
- «Обучение» не должно размножать тысячи почти одинаковых шаблонов; дедуп, TTL и измеренный размер пакетов. P95/P99 и запас BotHost измерять фактически.
- Не работает GitHub/сломанный хэш/запрещённое поле/повреждённый JSON ⇒ прошлый валидный пакет и отсутствие новых прав/санкций, без падения бота.
- Проверка PR (CI), принятие в main и подтверждение версии на живом BotHost — **три разных статуса**.

**Ближайший этап:** K0 + дизайн K1 после текущего игрового CI ImPULS; весь план сам по себе не является реализацией новых пакетов и не включает автоматическое обучение на сообщениях.
